# orbit-site agent instructions

Only what the global instructions and shared skills do not already cover.

- The Orbit family (`ai/orbit`, `ai/orbit-launcher`, `ai/orbit-site`, `ai/orbit-base-image`) is one project (Orbit ADR-0036, `ai/orbit`, `docs/adr/0036-the-orbit-family-is-one-project.md`): each repo's files, layout and scripts are the whole project's own, never designed around as an outside system. The launcher owns install, update, repair and removal; removal work belongs in the launcher, not a separate tool in Orbit.
- When work here needs a change in another of the four, do not make it from here: file an issue there with the design fully worked out, labelled `cross-repo`, in that repo's nearest open milestone, and link it from this repo's issue, parked as blocked. That repo's session builds and closes it; on resuming, check blocked issues, and bump any pin once the other repo has released. A `cross-repo` issue is ordinary work in its milestone. ADR-0036 still covers reading sibling repos and one-line pin or doc fixes (owner, 2026-10-22: avoids two sessions editing one repo at once).

## Rules and traps

- This is Orbit's public website: plain HTML, CSS and ES modules, no build step; `README.md` has the layout. It only *describes* Orbit. Features, installer behaviour and a doc's wording belong in `ai/orbit` and `ai/orbit-launcher`; a change there that alters what the public is told belongs here too.
- Pages serves `main`; the GitLab-to-GitHub mirror push is the release. Nothing is filed, pushed or merged on GitHub by hand. Issues #1 and #2 exist on both hosts; from #3 on, GitLab only.
- Generated `assets/docs/` is never edited by hand. Its pictures are copied in (`assets/docs/img/`, named by content hash); one the import cannot copy becomes a link.
- `assets/door/` is an interface Orbit copies unchanged (ADR-0001; the folder's `README.md` has it): change its entry point, slots or stylesheet contract deliberately and say so in the commit, since a break shows in Orbit's import merge request, not here. Site and Orbit differ by a setting or slot, never an edit to the folder. Run `node tools/door-markup.mjs` after editing the module. Nothing the Orbit app uses may load from an outside source (owner, 2026-10-20): the lint refuses any http, https or `//host` address in the folder but the SVG namespace.
- Nothing on the site loads from a third party either (owner, 2026-10-27, replacing 2026-10-20's "outside sources are fine for the site"): every font, script, style and picture is hosted here. Links to other sites are fine; loading from them is not.
- Branches are `dev -> main`, no `preview` (recorded exception in `~/.config/agents/EXCEPTIONS.md`): Pages serves one branch, so a `preview` would prove nothing. Never add or "restore" one.
- Nothing is pushed to `main` by hand: the nightly import opens a merge request that merges itself, and imports reach `dev` by back-merge after a promotion.
- Never ask the owner to update the main checkout's `dev` (`merge --ff-only gitlab/dev`); start work from `gitlab/dev` in a worktree and leave the main checkout alone. Auto mode refuses that merge, and handing it over every session cost the owner a step each time (owner, 2026-10-30).
- Check a change with `sh tools/ci/lint.sh` and `sh tools/ci/lint-test.sh`; serve it with `node tools/ci/serve.mjs`.
- The journey (`tools/ci/journey.mjs`) is the gate's live check and is never optional on promotion: a merge request into `dev` runs only the browser tests its change touches (ADR-0005), promotion to `main` runs everything. Before a push, run lint and `sh tools/ci/node-tests.sh` only; leave the live check and coverage to CI (by hand, `sh tools/ci/journey-local.sh` runs what changed against `dev`, `--all` the full run) (owner, 2026-10-24: local runs duplicated CI and cost hours).
- Coverage is a ratchet (`tools/ci/coverage-floors.json`, `README.md` has the mechanism): the `coverage` job fails if a file's line coverage is below its floor (every file on a full run, only the changed files on a merge request's partial run). Floors are raised from three full CI runs, never local ones: `sh tools/ci/coverage-fetch.sh JOB JOB JOB`, then the `node tools/ci/coverage.mjs --raise` it prints; never lower one to pass. The full local run is `sh tools/ci/coverage-run.sh`.
- WebGL needs headed Firefox under Xvfb with software GL; headless draws no world. `journey-local.sh` does this.
- No test depends on how fast the runner draws: CI has no GPU and shared CPUs, so timings vary wildly and prove nothing. Where the door takes a path on a speed verdict, the test forces it (`?fit=skip`, `?rich`, `?lean`, `?level=`) and checks behaviour only; the owner judges speed on real browsers (owner, 2026-10-14, after door-lows L3 failed three times on a busy runner).
- Real-device Safari runs are phone only: never ask the owner for a desktop Safari run (owner, 2026-10-22).
- The import is two jobs (#18): `import_docs` runs npm and the import with no token and hands on `assets/docs/` and `import-warnings.txt` (#82) as an artifact; `publish_docs` fetches that untrusted archive itself (it takes no artifacts through `needs`, so a dotenv report cannot set its variables), checks every entry, the docs' shape (`tools/ci/docs-shape.mjs`, sources in `tools/docs-sources.json`) and their markup against an allow-list of what the import writes (`tools/ci/docs-markup.mjs`; a new tag or attribute the import writes goes on its table), and pushes the branch and merge request; last, it rewrites the one "Docs import warnings" issue, a step that never fails the job. The Maintainer token `ORBIT_SITE_IMPORT_TOKEN` is scoped to the `docs-import` environment and only `publish_docs` uses it; never give it to another job or name it in `tools/ci/nightly-import.sh` (the lint refuses both). The guard is the variable's settings (CE has no protected environments): environment scope `docs-import` and the Protect flag, so only a job in that environment, in a protected-branch pipeline, gets the token. A new job in that environment needs a Maintainer's merge into `main` or `dev`, and the lint refuses any job but `publish_docs` that names `docs-import`. `RENOVATE_TOKEN` and `GITHUB_COM_TOKEN` are scoped the same way to the `renovate` environment, which only the `renovate` job joins. The runner cannot reach GitLab over SSH, so no deploy key.
- Replacing, adding or removing a picture changes `MEDIA` in `sw.js` (not under `assets/docs/`: the import's pictures are named by content hash); editing an inline `<script>` changes its hash in that page's policy meta. The lint prints the value to paste for both.
- Approved third-party content and its credits are listed in `README.md`; `marked`, `sharp`, `js-yaml` and `typescript` (dev only, for the door type check) versions are pinned only in `tools/package.json`.
- `package.json` only in `tools/`; never commit `node_modules`. The lint refuses both at the top level only.
- Mockups are shown to the owner only from the local design container (`orbit-site-design-host`, nginx, ports from 8307), with direct links in chat; never uploaded to issues or published on Pages (owner, 2026-10-21). Starting it needs no go-ahead: a standing auto-mode rule in the Claude settings allows it.
