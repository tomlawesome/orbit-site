The launcher

A command centre for your server

Orbit ships with its own terminal application for the whole lifecycle of a deployment. Full screen, a starfield, and a small set of clear choices.

You don't install the launcher separately. Orbit builds, signs and ships it alongside itself, and the one-line install verifies it before running it. Afterwards, run orbit-launcher from the deployment directory whenever you need it.

The menu

Install

Deploys Orbit for the first time. Choose a profile, confirm, and watch the installer run in the console. It stops and asks if it needs configuration only you can provide.

Update

Pulls the latest Orbit into the existing deployment. Configuration is preserved; nothing is deleted.

Repair

Reads the deployment without changing it, lists what it found, and proposes repairs. Safe repairs run in place; rotating database credentials takes a passphrase-protected backup first and verifies it.

Remove

Stops Orbit's containers. Files and data volumes stay on disk, and the final screen gives you the exact command to remove them if that's what you want.

The mission console

Orbit's installer emits a plain, versioned stream of status events as it works, and the console renders them. Success and failure are judged from those events and the exit code, never from parsing prose, so what you see is what the installer actually did. A run that fails before committing rolls the deployment directory back to how it was.

Arrival

Where it runs

  • Linux only: Debian, Ubuntu and similar. It runs on the server being managed, not as a desktop app.
  • On launch it makes one non-blocking check for a newer stable release and shows a small notice if there is one. It never fetches or changes anything by itself. Set ORBIT_LAUNCHER_NO_UPDATE_CHECK=1 to turn the check off.
  • Written in Go, using Bubble Tea for the full-screen event loop and Lip Gloss for layout.
