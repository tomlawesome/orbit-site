Get into Orbit

One command on a Linux host. It verifies everything it downloads before running any of it, then hands over to the launcher for a guided install.

Requirements

hostLinux — Debian, Ubuntu or similar · linux/amd64 images
runtimeDocker with Compose v2, and curl
memory~4 GiB for ClamAV, on by default
reachan HTTPS reverse proxy in front of Orbit's port
gitnot required — nothing is cloned

A deployment needs compose assets and a published image, not source. ClamAV can be disabled, but Orbit will show a persistent warning and mark later uploads as unscanned. Plain HTTP is supported only on loopback.

The one line

From an empty directory on the host:

$curl -fsSL https://raw.githubusercontent.com/tomlawesome/orbit/main/scripts/get-orbit.sh | bash

The directory you run it in becomes the deployment directory: where Orbit keeps its configuration (.env-orbit), its private secrets (.orbit-secrets/) and the compose files it takes from the image.

To pin a specific stable release rather than the latest, set ORBIT_VERSION=vX.Y.Z in the environment first.

What gets verified first

get-orbit.sh is deliberately short and readable. Before it runs anything it:

  1. downloads the signed release manifest and checks its signature against a public key embedded in the script;
  2. downloads the launcher and the installer named by that manifest;
  3. checks every file's SHA-256 against the manifest;
  4. if cosign is installed, checks a second, independent signature too.

Only once all of that passes does it hand off to the launcher. It fetches stable releases only. The full catalogue of what each script guarantees is docs/installer-guarantees.md.

The install itself

The launcher asks you to choose a deployment profile (Standard is the one available today), confirms, and runs Orbit's installer inside its console. The installer:

  • pulls the published image and resolves it to an immutable digest. That digest is what runs; a tag is only ever read to resolve it;
  • takes the compose files and operator scripts out of that same image, so a compose file cannot drift from the image it configures;
  • creates .env-orbit and generates independent 256-bit session, database and document-encryption secrets under .orbit-secrets/;
  • validates the rendered Compose configuration and starts the services;
  • withholds completion until PostgreSQL is healthy, Orbit's health endpoint reports ready, ClamAV is healthy and each selected optional service passes its probe.

If the installer needs something only you can provide, it stops safely and asks. If it fails before committing, it restores the previous file state. The target directory is not changed until the final review is accepted.

Signing in. By default Orbit uses local password accounts only. If you also want sign-in through an identity provider, the installer collects the public HTTPS origin, the OpenID Connect issuer, client ID and, privately, the client secret. See docs/authentication.md.

Claim your instance

A fresh Orbit has no administrator and is unclaimed. At the end of start-up it generates a one-time claim code, keeps it only in memory, and prints it as the last line of the container's own log:

docker compose --env-file .env-orbit logs orbit-app

Open the link on the last line, or type the code on the sign-in screen, to create the first administrator. That person then names the first system: the household's name, time zone, currency and starting sections.

Keeping it running

Run orbit-launcher again from the deployment directory at any time. Its menu covers the rest of the lifecycle:

Update

Pulls the latest Orbit into this deployment. Existing configuration is preserved; nothing is deleted.

Repair

Diagnoses the deployment and proposes repairs. Safe ones run without changing data; credential rotation takes a verified backup first.

Remove

Stops the containers. Your mail, documents and configuration stay on disk, and the screen shows exactly how to remove them if you choose to.

Before an upgrade

Create and verify a database backup with scripts/backup.sh, and keep an owner-only copy of the exact pre-upgrade .env-orbit beside it. scripts/restore.sh puts both back if a migration goes wrong. The README's Run with Docker section has the exact commands.

Optional services

The standard stack is Orbit, PostgreSQL and ClamAV. Two more are available and off by default, because they add host memory and are never needed for normal operation:

  • Tika for OCR and text extraction from documents.
  • Ollama as a local model server. It uses no cloud models and does not download a model automatically.

Both are selected in .env-orbit with COMPOSE_PROFILES, so turning one on later is a one-line edit rather than a different command. Neither has a published host port.

Building from source

Building is a developer workflow rather than an installation choice, so the installer doesn't offer it. Clone the repository and build explicitly:

git clone https://github.com/tomlawesome/orbit.git && cd orbit
bash scripts/configure.sh
bash scripts/build-container.sh

The README covers the rest: runtime configuration, starting with Compose, and the configuration contracts.
